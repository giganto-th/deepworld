# DeepWorld — เว็บแอปแผนที่โลก 3 มิติแสดงความสูงของเปลือกโลก

เอกสารวิจัย วิเคราะห์ และออกแบบ (ฉบับที่ 1 · 19 ต.ค. 2026)

---

## 1. เป้าหมายและขอบเขต

สร้างเว็บแอปที่แสดง **โลกทั้งใบเป็นทรงกลม 3 มิติ** โดยยกพื้นผิวขึ้นลงตามความสูงจริงของ **เปลือกโลก ทั้งบนบกและใต้มหาสมุทร**
ผู้ใช้หมุน ซูม และสำรวจภูเขา ร่องลึกก้นสมุทร และสันเขากลางมหาสมุทรได้ในเบราว์เซอร์ โดยไม่ต้องติดตั้งอะไรเพิ่ม

| ต้องมี (MVP) | ควรมี (เฟส 2) | ไว้ทีหลัง (เฟส 3) |
|---|---|---|
| ลูกโลก 3D ที่มีความสูงทั้งบนบกและใต้ทะเล | ระดับรายละเอียดแบบปรับตามการซูม (LOD) ไปจนถึงระดับ ~30 ม. | การ์ตูนอธิบายทางการศึกษา และทัวร์นำชม |
| ปรับการขยายความสูงได้ (1×–100×) | ข้อมูลแผ่นดินไหวและภูเขาไฟแบบเรียลไทม์ | ภาพตัดขวางของชั้นเปลือกโลก (CRUST1.0) |
| เปิด/ปิดน้ำทะเล และจำลองระดับน้ำทะเล | การวัดระยะทางและกราฟภาพตัดขวาง (profile) ของพื้นที่ | รองรับ VR/AR (WebXR) |
| ไล่สีตามระดับความสูง (hypsometric tint) + การให้แสงเงา | ชั้นข้อมูลภาพถ่ายดาวเทียม | |
| แสดงแนวรอยต่อแผ่นเปลือกโลก | | |
| ชี้เมาส์แล้วเห็นพิกัดและความสูง | | |
| ปุ่มบินไปยังจุดสำคัญ (เช่น เอเวอเรสต์ ร่องลึกมาเรียนา) | | |

## 2. ผลการวิจัย

### 2.1 แหล่งข้อมูลความสูง (DEM / Bathymetry)

| ชุดข้อมูล | ความละเอียด | ครอบคลุม | จุดเด่น / ข้อจำกัด | สัญญาอนุญาต |
|---|---|---|---|---|
| **GEBCO_2025 Grid** | 15 arc-sec (~450 ม.) | บก + ทะเลทั้งโลก | มาตรฐานงานด้านมหาสมุทร ใช้ SRTM15+ v2.7 เป็นฐาน มีรุ่นที่แสดงภูมิประเทศใต้แผ่นน้ำแข็ง (Greenland/Antarctica) ไฟล์ทั้งโลกในรูป netCDF ขนาดใหญ่มาก | Public domain (ต้องอ้างอิงแหล่งที่มา) |
| **NOAA ETOPO 2022** | 15 / 30 / 60 arc-sec | บก + ทะเล | มีทั้งรุ่น "ice surface" และ "bedrock" ดาวน์โหลดได้ง่าย เหมาะใช้เป็น base layer | Public domain |
| **Copernicus DEM GLO-30** | 30 ม. | เฉพาะบก | รายละเอียดสูงมาก มีบน AWS Open Data ในรูป COG | ใช้ได้ฟรี ต้องอ้างอิงแหล่งที่มา |
| **AWS Terrain Tiles (Mapzen/Joerd)** | ถึงระดับ z14 | บก + ทะเล (ทะเลมาจาก ETOPO1) | **แบ่งเป็น tile สำเร็จรูป มี CORS `*` เรียกจากเบราว์เซอร์ได้ทันที** ใช้รูปแบบ Terrarium PNG: `h = R*256 + G + B/256 − 32768` ข้อมูลทะเลค่อนข้างหยาบ | Open (ต้องแสดง attribution) |
| MapTiler / Mapbox Terrain-RGB | ถึงระดับ z12–z15 | บก (+ทะเลบางส่วน) | ใช้ร่วมกับ SDK ได้ง่าย แต่ต้องใช้ API key และมีโควตา | มีค่าบริการตามปริมาณการใช้ |

**ข้อสรุป:** ต้นแบบใช้ **AWS Terrain Tiles** เพราะเรียกใช้ได้จากเบราว์เซอร์โดยตรง ไม่ต้องมี key และมีข้อมูลก้นทะเล
เมื่อขึ้นระบบจริง ควรทำ pipeline สร้าง tile เองจาก **GEBCO_2025 (ทะเล) + Copernicus GLO-30 (บก)** เพื่อให้ได้ข้อมูลก้นทะเลที่ดีกว่า

### 2.2 ข้อมูล "เปลือกโลก" เพิ่มเติม (ชั้นข้อมูลซ้อน)

| ข้อมูล | แหล่ง | ใช้ทำอะไร |
|---|---|---|
| รอยต่อแผ่นเปลือกโลก PB2002 (Bird, 2003) | GeoJSON โดย fraxen/tectonicplates | เส้นแนวรอยต่อบนลูกโลก ← **ใช้แล้วในต้นแบบ** |
| เขตจังหวัด (77) และตำบล (7,367) ของไทย | GeoJSON จาก chingchai/OpenGISData-Thailand (CC BY 4.0, ข้อมูลขอบเขตจากกรมการปกครอง) | เส้นเขตจังหวัดและตำบล ชื่อ ต./อ./จ. ใต้เคอร์เซอร์ และเมนูบินไปยังจังหวัด ← **ใช้แล้วในต้นแบบ** |
| แผ่นดินไหว | USGS Earthquake GeoJSON feed (เรียลไทม์) | จุดแสดงแผ่นดินไหวตามความลึกและขนาด |
| ภูเขาไฟ | Smithsonian GVP | จุดแสดงภูเขาไฟ |
| ความหนาของเปลือกโลก | CRUST1.0 (กริด 1°) | ระบายสีตามความหนาของเปลือกโลก หรือแสดงภาพตัดขวาง |
| อายุของพื้นมหาสมุทร | Seton et al. 2020 / EarthByte | ระบายสีตามอายุของพื้นทะเล ทำให้เห็น sea-floor spreading |

### 2.3 เทคโนโลยีการเรนเดอร์ 3D บนเว็บ

| ตัวเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **CesiumJS** | ลูกโลกที่แม่นยำตามมาตรฐาน (WGS84) ทำ LOD terrain ให้แล้ว (quantized-mesh) และรองรับ 3D Tiles | ไฟล์ใหญ่ (~3–4 MB) terrain เริ่มต้นต้องใช้ Cesium ion token ปรับแต่ง shader ได้ยาก (เช่น การขยายความสูงหรือการไล่สีใต้ทะเลแบบที่ต้องการ) |
| **MapLibre GL JS v5+** | ตั้งแต่ v5.0 (ม.ค. 2025) มี globe projection และรองรับ terrain จาก `raster-dem` แบบ Terrarium เป็น open source | ออกแบบมาเพื่อมุมมองใกล้พื้น พอซูมออกเต็มโลก terrain ยกตัวได้น้อย จึงแสดงทั้งโลกแบบ "นูนชัด" ได้ยาก |
| deck.gl `TerrainLayer` | สร้าง mesh จาก tile ความสูงได้ (ใช้ martini/delatin) | ใช้ globe view ได้แค่ในระดับทดลอง |
| **Three.js + shader เขียนเอง** | ควบคุมได้ทั้งหมด ทั้งการขยายความสูง การไล่สีบก/ทะเล การจำลองระดับน้ำ และเอฟเฟกต์บรรยากาศ ไฟล์เล็ก (~170 KB gz) | ต้องเขียน LOD และระบบ tile เอง |

**ข้อสรุป:** โจทย์นี้เน้นการเห็น **"โลกทั้งใบ" แบบนูนชัด** ทั้งบกและก้นทะเล โดยปรับการขยายความสูงได้มาก ซึ่งไลบรารีแผนที่ทั่วไปทำได้ไม่ดี
จึงเลือก **Three.js + custom shader** เป็นแกนหลัก
หากในอนาคตต้องการซูมลงไปดูพื้นที่ระดับเมือง ให้ทำ LOD quadtree เอง (หัวข้อ 4.4) หรือเพิ่มโหมด "ซูมใกล้" ที่สลับไปใช้ MapLibre/Cesium

## 3. การวิเคราะห์ความต้องการเชิงเทคนิค

- **สเกล:** รัศมีโลก 6,371 กม. ส่วนความสูงรวมจากยอดเอเวอเรสต์ (+8.85 กม.) ถึงก้นร่องลึกชาเลนเจอร์ (−10.9 กม.) อยู่ที่ ~19.8 กม. หรือแค่ **0.3% ของรัศมี**
  ถ้าแสดงตามสเกลจริงจะแทบมองไม่เห็นความนูน จึง **ต้องมีตัวคูณการขยายความสูง (vertical exaggeration)** ค่าที่เหมาะคือ 20–50 เท่า
- **ปริมาณข้อมูล:** กริดทั้งโลกที่ ~20 กม./พิกเซล คือ 2048×1024 จุด หรือ 2M ค่า ส่วนที่ ~10 กม. คือ 8M ค่า ทั้งสองขนาดใส่ใน GPU texture ขนาด 16-bit ได้สบาย
  ถ้าละเอียดกว่านี้ต้องใช้ tile และ LOD
- **การฉายแผนที่:** ข้อมูล tile เป็นแบบ Web Mercator ซึ่งไม่มีข้อมูลเลยละติจูด ±85.05° จึงต้อง reproject เป็น equirectangular ก่อนนำไปพันรอบทรงกลม
  ขั้วโลกใช้ค่าจากขอบแทน ซึ่งเป็นข้อจำกัดของต้นแบบ ระบบจริงควรใช้ GEBCO ที่ครอบคลุมถึงขั้วโลก
- **ประสิทธิภาพ:** mesh ขนาด 1024×512 segment มีประมาณ 1M สามเหลี่ยม ซึ่งเรนเดอร์ที่ 60fps ได้บน GPU ทั่วไปในปัจจุบัน
  ส่วนแสงเงาคำนวณใน fragment shader จาก texture จึงได้รายละเอียดมากกว่า mesh

## 4. สถาปัตยกรรม

### 4.1 ภาพรวม

```
 ┌───────────────────────── Data pipeline (offline, เฟส 2) ─────────────────────────┐
 │ GEBCO_2025 + Copernicus GLO-30 → GDAL merge/resample → encode Terrarium PNG/WebP │
 │                → tile pyramid z0–z12 (+ quantized-mesh ถ้าใช้ Cesium) → R2/S3 + CDN│
 └──────────────────────────────────────────────────────────────────────────────────┘
                                         │ HTTPS (CORS)
 ┌─────────────────────────────── Browser ──────────────────────────────────────────┐
 │  ElevationLoader ── ดึง tile → decode Terrarium → Float32 (Web Worker ในเฟส 2)     │
 │        │                                                                          │
 │  Reprojector ── Mercator → Equirectangular (+ clamp ขั้วโลก)                        │
 │        │                                                                          │
 │  GPU: HalfFloat height texture ── Vertex shader: displace ตามรัศมี                    │
 │                                └─ Fragment shader: normal จาก gradient, ไล่สี, น้ำ     │
 │  Overlays: แนวรอยต่อแผ่นเปลือกโลก (LineSegments), แผ่นดินไหว (Points, เฟส 2)            │
 │  UI: แผงควบคุม · readout ใต้เคอร์เซอร์ · ปุ่มบินไปยังจุดสำคัญ                              │
 └──────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 เทคนิคเรนเดอร์

1. **Displacement:** ใช้ `SphereGeometry` แปลง UV เป็นละติจูด/ลองจิจูด แล้ววางจุดยอดที่ `dir × (1 + h × exaggeration / R)`
   ถ้าเปิดโหมดน้ำทะเล จะใช้ `max(h, seaLevel)` แทน `h`
2. **Normal / Hillshade:** หา gradient ของ h ในทิศตะวันออกและทิศเหนือ (หน่วยเมตร) ด้วย finite difference จาก texture
   จากนั้นแปลงเป็น normal ในกรอบ ENU แล้วแปลงต่อเป็น world space ทำให้ได้เงาละเอียดในระดับพิกเซล
3. **ไล่สี:** ใช้ ramp texture ขนาด 1D ช่วง −11,000 ถึง +9,000 ม. ไล่สี **ดำ (ก้นทะเลลึกสุด) → น้ำเงิน → เขียว (ที่ราบลุ่ม) → น้ำตาล (ภูเขา)**
   ตรงระดับน้ำทะเลตัดสีจากฟ้าอ่อนเป็นเขียวเข้มทันที เพื่อให้เห็นแนวชายฝั่งชัด
4. **แสง:** ใช้ "ไฟส่องตามกล้อง" ที่เอียงไปทางซ้ายบน เพื่อให้เห็นภูมิประเทศชัดจากทุกมุม และเพิ่ม atmosphere glow ด้วย fresnel
5. **ภาพรายละเอียดตามการซูม (detail patch, ทำแล้ว):** เมื่อกล้องลงต่ำกว่า 0.5 R ระบบจะเลือกระดับ tile ที่ทำให้ 1 texel ใกล้เคียงกับ 1 พิกเซลบนจอ (z5–z12, สูงสุด 144 tiles)
   จากนั้นโหลดเฉพาะบริเวณที่มองเห็น สร้างเป็น surface ซ้อนบนลูกโลก แล้วเจาะรู (discard) ลูกโลกตรงบริเวณนั้น
   เมื่อซูมระดับจังหวัดจะได้ภาพละเอียดประมาณ 40–300 ม./พิกเซล ระบบใช้ LRU cache 600 tiles และยกเลิก request เก่าเมื่อมุมมองเปลี่ยน
6. **มุมมอง 3D รายจังหวัด (ทำแล้ว):** คลิกที่จังหวัดหรือเลือกจากเมนู กล้องจะบินไปโคจรรอบจุดกลางของจังหวัด เอียง 66° จากแนวดิ่ง (กล้องอยู่สูงจากแนวขอบฟ้าประมาณ 24°) และปรับการขยายความสูงเป็น 4×
   OrbitControls จะถูกสร้างใหม่โดยตั้ง up เป็นทิศตั้งฉากกับพื้นตรงนั้น ทำให้ลากเพื่อหมุนหรือเอียงได้ และลากด้วยปุ่มขวาเพื่อเลื่อนไปตามพื้นได้
   ระบบจะโหลด detail patch ให้ครอบคลุมทั้งจังหวัดที่ zoom ละเอียดที่สุดภายในงบ 240 tiles และไม่เกินขนาด texture สูงสุดของ GPU (สูงสุด 8192 px)
   ผลที่ได้คือจังหวัดใหญ่ เช่น เชียงใหม่ ได้ z11 (~75 ม./พิกเซล) ส่วนจังหวัดเล็ก เช่น ภูเก็ต ได้ z12 (~38 ม./พิกเซล)
   การ decode ทำทีละ tile ผ่าน canvas ขนาด 256 px ใบเดียว จึงไม่ติดเพดานพื้นที่ canvas ของเบราว์เซอร์ (Safari ~16.7 Mpx)
   tile ระดับ z10 ขึ้นไปไม่มีข้อมูลความลึกทะเล (ทะเลเป็น 0 ม.) และมีหลุมข้อมูลผิดพลาดตามชายฝั่ง จึงเติมค่าจากกริดโลก (ETOPO) แทน
7. **หมุดจุดสูงสุด/ต่ำสุด:** วาดขอบเขตจังหวัดลงบน canvas ขนาดเท่ากริด (even-odd fill) แล้วไล่หาค่าสูงสุดและต่ำสุดเฉพาะพิกเซลที่อยู่ในจังหวัด
   จุดต่ำสุดนับเฉพาะพื้นดินที่สูง ≥ 0 ม. เพื่อตัดส่วนที่เป็นทะเลในขอบเขตจังหวัดชายฝั่งออก
   ก่อนคำนวณจะลบ spike และหลุมในข้อมูล Terrain Tiles: spike ที่สูงกว่า median 3×3 เกิน 150 ม. จะถูกแทนด้วย median 3×3 ส่วนหลุมที่ต่ำกว่า median 5×5 เกิน 60 ม. จะถูกแทนด้วย median 5×5
   (ตัวอย่างเช่น เชียงใหม่มีแถวข้อมูลผิดพลาดที่ −892 ถึง +2,718 ม. บนที่ราบสูงประมาณ 400 ม.)
   ปักหมุด 3D (ก้านพร้อมหัวกลม) และป้ายแสดงความสูง ตัวอย่างเช่น เชียงใหม่ได้ 2,565 ม. ที่ 18.588°N 98.486°E ซึ่งตรงกับดอยอินทนนท์
8. **ข้อมูลระดับตำบลใต้เคอร์เซอร์:** โหลดขอบเขตตำบลทั้งประเทศ (~2 MB แบบบีบอัด) แล้วจัดกลุ่มตามรหัสจังหวัด
   เวลาชี้เมาส์จะหาจังหวัดก่อน แล้วทดสอบเฉพาะตำบลในจังหวัดนั้น (กรองด้วย bbox ก่อน แล้วจึงทำ point-in-polygon) จากนั้นแสดงเป็น "ต.… อ.… จ.…" (กรุงเทพฯ ใช้แขวง/เขต)
   ในมุมมอง 3D รายจังหวัดจะแสดงเส้นเขตตำบลของจังหวัดนั้นด้วย
9. **ฉากหลังอวกาศ:** ใช้ดาว 9,000 ดวงที่มีสีและขนาดต่างกัน และมีแถบทางช้างเผือก วางบนทรงกลมที่ยึดตำแหน่งกล้องไว้ทุกเฟรม จึงอยู่ด้านหลังลูกโลกเสมอ
10. **หน้า `/thai` (เฉพาะประเทศไทย):** ใช้ `index.html` และ `main.js` ชุดเดียวกัน แต่สลับเป็นโหมดไทยเมื่อ path เป็น `/thai`
   แทนลูกโลกด้วย surface ประเทศไทยผืนเดียว (5.5–20.6°N, 97.2–105.8°E) โหลดแบบก้าวหน้า คือ z7 เป็นภาพตัวอย่างก่อน แล้วจึงสลับเป็น z9 (~300 ม./พิกเซล, 299 tiles)
   ทุก surface ใช้ mask จากขอบเขตจังหวัดรวมกัน (canvas 4096 px เป็น texture R8) และ discard ทุกอย่างนอกประเทศไทย ทำให้ประเทศไทยลอยอยู่กลางอวกาศ
   ช่วงสูงสุด–ต่ำสุดคำนวณเฉพาะพื้นที่ในประเทศไทย ส่วนมุมมอง 3D รายจังหวัดและข้อมูลตำบลยังใช้ได้เหมือนเดิม
   ตอนพัฒนาใช้ `serve.py` จัด route `/thai` ส่วนบน GitHub Pages ใช้ workflow `.github/workflows/pages.yml` คัดลอก `index.html` ไปเป็น `thai/index.html` แล้วใส่ `<base href="../">`
11. **10 อันดับของโลก:** อ่านจาก `data/world-extremes.json` ข้อมูลความสูงและความลึกตรวจสอบกับวิกิพีเดียแล้ว (เช่น Horizon Deep 10,823 ม., Izu–Ogasawara 9,826 ม., Japan Trench 8,046 ม.)
   ภาพมาจาก Wikimedia Commons โดยระบุผู้ถ่ายและสัญญาอนุญาต ส่วนคำอธิบายย่อมาจากวิกิพีเดียไทย/อังกฤษ
   หมุดเป็นป้ายแสดงอันดับ ซึ่งจะวางในช่องว่างที่ใกล้จุดจริงที่สุดโดยไม่ทับป้ายอื่นหรือจุดอื่น และมีเส้นนำโยงกลับไปยังตำแหน่งจริง
12. **2 ภาษาและ SEO:** ข้อความทั้งหมดอยู่ใน `src/i18n.js` ภาษาดูจาก path (`/en/…`) ทำให้แต่ละภาษามี URL ของตัวเองสำหรับ search engine
   `tools/build.py` สร้างหน้า `/`, `/thai/`, `/en/`, `/en/thai/` จาก `index.html` ไฟล์เดียว โดยใส่ `<base>`, `<html lang>` และ SEO block (title, description, canonical, hreflang, OG, Twitter, JSON-LD) ให้แต่ละหน้า
   แล้วสร้าง `sitemap.xml` และ `robots.txt` ด้วย ส่วน `serve.py` ใช้ฟังก์ชันเดียวกันตอนพัฒนา
13. **ถนนและชื่อสถานที่บน 3D:** เดิมทดลองทำแผนที่ย่อ 2D ด้วย Leaflet แต่เปลี่ยนมาวางข้อมูลบนภูมิประเทศ 3D โดยตรง (`src/overlay.js`)
   ใช้ tile แบบโปร่งใส 2 ชั้นของ Esri ได้แก่ World Transportation (ถนนพร้อมชื่อและเลขทางหลวง) และ World Boundaries and Places (ชื่อสถานที่และเขตปกครอง)
   ซึ่งไม่มีพื้นสีทึบ จึงยังเห็นสีและเงาของภูมิประเทศ
   แต่ละ surface (ลูกโลก, ประเทศไทย, detail patch, จังหวัด) โหลด tile ในช่วง Web Mercator ของตัวเองลง canvas แล้วใช้เป็น texture (มี mipmap และ anisotropy)
   shader แปลง lat/lon เป็นพิกัด tile แล้วผสมสีหลังคำนวณแสงเงา ทำให้ตัวอักษรอ่านง่าย ถ้าช่วงนั้นมีเกิน 160 tiles จะลดลงไปใช้ zoom ที่หยาบกว่า
   เมื่อมี detail patch ระบบจะซ่อน overlay ของ surface ฐาน เพื่อไม่ให้ตัวอักษรขนาดใหญ่และเบลอปรากฏรอบ ๆ patch
   ต้องแสดง attribution: Esri, HERE, Garmin, © OpenStreetMap contributors, GIS user community
14. **ระดับน้ำทะเลตามปีและการคาดการณ์ (`src/sealevel.js`):** ใช้ค่าเฉลี่ยทั้งโลกเทียบค่าเฉลี่ย พ.ศ. 2538–2557 ซึ่งใกล้กับช่วงเก็บข้อมูล SRTM (พ.ศ. 2543) จึงใช้ค่านี้เป็นระดับน้ำบนแผนที่ได้ตรง ๆ
   ค่าที่วัดได้: IPCC AR6 (พ.ศ. 2444–2561 สูงขึ้น 0.20 ม.; 1.3 → 1.9 → 3.7 มม./ปี) และเติมถึง พ.ศ. 2567
   การคาดการณ์: AR6 ตาราง 9.9 ปี 2030/2050/2090/2100/2150 ของ SSP1-1.9 ถึง SSP5-8.5 (median และ likely range) และกรณี low confidence ของ SSP5-8.5 ใช้ interpolate แบบเส้นตรงระหว่างปี
   การวิเคราะห์: ระดับน้ำเฉลี่ยทั้งโลกภายใน พ.ศ. 2643 (+0.4 ถึง +1 ม.) ท่วมพื้นที่ในข้อมูล ~300 ม./พิกเซล ได้เพียงหลักร้อย ตร.กม.
   แต่ความเสี่ยงจริงของกรุงเทพฯ มาจากแผ่นดินทรุด (1–3 ซม./ปี) น้ำขึ้นสูงสุด และคลื่นพายุ จึงมีตัวเลือกบวกแผ่นดินทรุด และปุ่ม +1/+2/+5 ม. ไว้ดูภาพรวมของกรณีที่รุนแรงกว่า
15. **แนวโน้มระยะยาว:** แผงระดับน้ำแบ่งเป็น 3 แท็บ: อดีต 26,000 ปี / พ.ศ. 2444–2693 / อนาคต 10,000 ปี
   อดีต: เส้นระดับน้ำทั้งโลก (ประมาณตาม Lambeck et al. 2014: −134 ม. เมื่อ ~21,000 ปีก่อน และ MWP-1A ~18 ม. ใน ~500 ปี) และเส้นอ่าวไทย (สูงสุด ~+4 ม. เมื่อ ~6,500 ปีก่อน) พร้อมคำอธิบายยุค
   อนาคต: ระดับน้ำที่หลีกเลี่ยงไม่ได้ตามระดับโลกร้อนสูงสุด จาก IPCC AR6 Box 9.4 (2,000 ปี / 10,000 ปี) โดยใช้ค่าปี 2150 จาก SSP ที่ใกล้เคียงกัน และ interpolate แบบเส้นตรงระหว่างช่วง
   ข้อจำกัด: ใช้ภูมิประเทศปัจจุบัน (ไม่รวมการทับถมของตะกอน การยกหรือยุบตัวของแผ่นดิน และ glacial isostatic adjustment ยกเว้นในเส้นอ่าวไทย)
16. **Picking:** ยิง ray ไปตัดทรงกลม แล้ววนแก้ค่ารัศมีด้วยความสูงที่จุดนั้น 3 รอบ จึงได้พิกัดที่แม่นยำแม้ตั้งค่าขยายความสูงไว้มาก

### 4.4 แผน LOD (เฟส 2)

- ใช้ **Chunked quadtree บนลูกบาศก์ที่ฉายเป็นทรงกลม (cube-sphere)** แต่ละโหนดเป็น patch ขนาด 64×64 พร้อม skirt เพื่อปิดรอยต่อระหว่าง patch
- เลือกระดับของ tile จาก screen-space error = (geometric error × ความสูงของ viewport) / (ระยะ × 2·tan(fov/2)) โดยกำหนดเกณฑ์ไว้ที่ 2px
- decode tile ใน **Web Worker** ใช้ cache แบบ LRU (~256 tile) และแสดง tile ระดับพ่อไปก่อนจนกว่า tile ลูกจะโหลดเสร็จ
- เป้าหมาย: 60fps บนแล็ปท็อป, 30fps บนมือถือระดับกลาง, ใช้หน่วยความจำ GPU ไม่เกิน 300 MB

## 7. ความเสี่ยง
